# Drafts exist outside production only, and the rule lives in one helper

A Post with `draft: true` needs to be readable while it's being written without being published. Three shapes were considered: build Drafts only under `astro dev`; build them everywhere and merely leave them out of the index; or build them everywhere except production. The middle option was rejected outright — it makes a Draft unlisted rather than unpublished, which is a distinction that disappears the moment anything links or crawls the URL, and the failure is silent. We build Drafts on the dev server and in Vercel preview deployments, and never in production, so a Draft can be read on a shareable preview URL while having no existence at all on the live site. That couples the content pipeline to `VERCEL_ENV`, accepted deliberately because the site is on Vercel and expected to stay there; if that changes, `draftsAreReadable` in `src/lib/posts.ts` is the single line to revisit.

**The predicate fails closed, and this is the part most likely to be "simplified" into a bug.** It tests `import.meta.env.DEV || VERCEL_ENV === 'preview'` — an allowlist — rather than the equivalent-looking `VERCEL_ENV !== 'production'`. The difference only shows up when the variable is unset, which is the case for a local `npm run build`, for CI, and for any host that isn't Vercel. Under the allowlist an unknown environment hides Drafts; under the negation it reveals them. The costs are not comparable: the first is an annoyance you notice immediately, the second publishes a Draft quietly and possibly permanently.

All Post lookups go through `getVisiblePosts()` in `src/lib/posts.ts` rather than filtering at each call site, and it sorts as well as filters, so a future listing (tag pages, an archive) gets both rules for free. The concern is specific: a call site that forgets the filter doesn't fail loudly, it publishes a Draft. This mirrors `formatPostDate` in `src/lib/date.ts`, which exists so the UTC pin can't be forgotten the same way. Because Drafts are filtered inside `getStaticPaths`, production emits no route for them at all — which also means Pagefind (#6), indexing built HTML, cannot index a Draft without any extra work.

Consequence worth stating: nothing in the repo exercises this. With no Draft committed and no test suite, the protection against regression is this document plus the comments at `draftsAreReadable`.

**Amended by #37 and #40:** the Visible Post manifest (`/posts.json`) now has a check. `npm run audit:manifest` re-derives the Draft set from Post frontmatter, deliberately without calling `getVisiblePosts()`, and fails if a Draft appears in the built manifest. The rule still has one production owner; the audit exists to disagree with it. There is now also a test suite (`npm test`), but it covers the publish planner and not the predicate above, which is still exercised only by the audit.
