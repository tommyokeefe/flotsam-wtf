# Use Astro Content Collections for posts

Posts were individual pages under `src/pages/posts/*.md(x)`, each with its own `layout:` frontmatter and no shared schema — every feature (post index, tags, search, thumbnails) would have had to independently glob and parse raw frontmatter. We moved posts to `src/content/posts/<slug>/index.md` (colocated images, own folder per post) with one Zod schema and a single `[...slug].astro` route, so `tags`, `image`, and `draft` are typed and validated in one place instead of re-implemented per feature. The trade-off: adding a post is no longer "drop a file and it's automatically a route" — it's data rendered through a shared route — and the per-post `layout:` override is gone (it wasn't being used for anything but consistency). Existing URLs (`/posts/wind`, `/posts/circle-of-concern`) are preserved by keeping slugs flat and equal to folder names.
